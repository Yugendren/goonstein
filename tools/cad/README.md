# The architecture kit

The compound started as stacked boxes: a window was a black rectangle painted on a wall, a column
was a cylinder, an eaves was the edge of a wedge. This is the kit that puts real architecture on
top of them -- and, because it is CAD rather than a mesh, the same kit is something you can open
in your own CAD tool, change a number, and rebuild.

Nothing here is borrowed. Every solid is generated by our own script from our own parameters.

    tools/cad/kitlib.py      the contract: axes, materials, the @piece registry, and helpers
    tools/cad/pieces/*.py    the pieces themselves, one function each
    tools/cad/obj_stage.py   the Blender half: weld, decimate, smooth, write the OBJ
    tools/cad/build_kit.py   the driver
    tools/cad/out/*.step     the editable CAD bodies
    assets/models/own/arch/  the game meshes the .part files place

## Regenerating it

CadQuery lives in a virtualenv beside the scripts, so it never touches the system Python:

    python3 -m venv tools/cad/.venv
    tools/cad/.venv/bin/pip install cadquery

Then:

    tools/cad/.venv/bin/python tools/cad/build_kit.py             # everything
    tools/cad/.venv/bin/python tools/cad/build_kit.py temple_dome # just one
    tools/cad/.venv/bin/python tools/cad/build_kit.py --list      # what there is

It prints a table of triangle counts and sizes and fails if a piece breaks a frame rule, blows
its triangle budget, or takes the kit over 30000 triangles in total. Blender is called once per
piece and the whole kit takes well under a minute.

## The frame, once and for all

Pieces are modelled the way a CAD tool wants them and converted on export.

    +Z is up. +X is along the width, and the piece is centred on X = 0.
    +Y is outward -- away from the wall it hangs on. Y = 0 is the mounting plane.
    The base of the piece is Z = 0.

    game (x, y, z) = cad (x, z, -y)

so a piece protrudes toward game -Z, which is the way every building on this island faces. Put a
window at the wall's own coordinates and it is already sitting on the wall, facing out.

A piece marked `free=True` -- a column, a baluster post, the dome, a finial -- is centred on Y as
well, because its axis is the thing you place, not its back face.

The Z = 0 rule is not a style preference. `src/model.c` rebases an OBJ's lowest vertex to Y = 0 on
load, so a piece that floats above its own origin in CAD silently drops onto it in game.
`build_kit.py` refuses to export one.

## How a piece reaches the game

`assets/models/own/arch/NAME.obj` is placed by a `.part` file exactly like any other model:

    piece models/own/arch/window_large.obj  2.4 1.35 -6.0  1 1 1  0 0 0  1.6 1.7 1.8  tex plaster_smooth 0.8

The fourth group is a *scale*, not a size -- these meshes already carry their real metres, so
`1 1 1` means "as drawn". Scaling is still how you resize a piece: `1.5 1 1.5` gives the villa a
fatter column than the wings get, from one mesh.

Some pieces may be stretched along X and some may not, and it is worth knowing which:

  * `cornice_run`, `pool_coping_run` and `stripe_panel` are pure extrusions -- their section is
    the same at every point along the run -- so scaling X just makes them longer. One piece scaled
    to `21 1 1` is a twenty-one metre cornice and one draw call.
  * `balustrade_run` and `roof_edge_run` have features that repeat along the run (balusters,
    barrel tiles). Stretching those stretches the balusters. Place N of them a metre apart
    instead; they are cut to butt cleanly with no half-baluster at either end.

## Colour and texture

Two things the engine already decided:

  * `model_from_triangles` gives every OBJ prop a single white texture, so an OBJ's own UVs can
    never be sampled. Nothing in this kit writes a UV. `tex NAME TILE` on the .part line projects
    a world texture in world space at TILE repeats per metre instead, which is why a piece's scale
    never stretches its stone.
  * `model.c` raises the MTL's `Kd` to the power 2.2 itself, so the `.mtl` carries sRGB. The
    `paint` material is deliberately the same 0.78 grey as `assets/models/shapes/paint.mtl`, which
    means every tint number already written in a `.part` file means exactly what it meant on a box.

So use `paint` for anything the level should be free to tint and texture, and a named colour only
where the colour is the point: `dark` and `glass` for the inside of an opening, `wood` for a
shutter, `gold` and `blue` for the temple. Because an OBJ is loaded as one mesh with per-vertex
colour, a whole window -- frame, sill, shutters, dark pane -- costs one draw call, and every copy
of it batches into the same instanced draw.

## Editing a piece in your own CAD tool

The STEP files in `tools/cad/out/` are the real bodies, coloured per material, Z up, in metres.
Open one, change it, and drop it back in as a mesh:

1. Edit `tools/cad/out/NAME.step` and export it as an OBJ or STL in **millimetres or metres**
   (either is fine -- `src/model.c` reads anything over 50 units across as millimetres), **Z up**.
2. Run it through the same game-mesh stage the kit uses, so it is welded, smoothed and budgeted
   the same way and lands in the same axes:

       blender -b --python tools/cad/obj_stage.py -- \
           assets/models/own/arch/NAME.obj 2000 paint:c7c7c7:/path/to/your.stl

   The last arguments are `material:hexcolour:file` -- one per colour you want in the piece.
3. If instead you want the kit to keep generating it, change the numbers in the piece's function
   in `tools/cad/pieces/` and rerun `build_kit.py`. That is the path that survives; a dropped-in
   OBJ is overwritten the next time the kit is built.

Either way the `.part` files that place the piece do not change, because the piece keeps its name,
its origin and its mounting plane.

## What is in it

Run `build_kit.py --list` for the current set. Roughly: windows in two sizes with sills and
shutters, a french door, a plain door, an arched opening, a wall column, a balustrade run and its
post, a cornice run, a roof tile edge run, a five-step stair, a pool coping run, a pergola bay,
the temple's drum and dome, a gold bird finial, a striped wall panel, a cistern cap and a lamp
bracket.

The dome is worth a note. `assets/levels/island.txt` says the Music Room's dome "left in a
hurricane", so the drum is what stands on the roof and the dome itself lies on the ground beside
the podium where the weather put it. The piece is still in the kit, still parametric, and putting
it back on the drum is one line.
